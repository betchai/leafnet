ABSTRACT

Mulberry (Morus spp.) leaves are the principal feed of silkworms, and foliar diseases — leaf rust, leaf spot, and leaf blight — directly reduce leaf yield and quality. Field diagnosis today still relies on manual visual inspection by trained personnel, which is slow, labor-intensive, and error-prone in large plantings. This study developed LEAFNET, a machine learning–driven system that classifies a mulberry leaf photo as healthy, leaf rust, leaf spot, or leaf blight, and reports the visual evidence and confidence behind every diagnosis. Guided by the Machine Learning Development Life Cycle, the system uses a MobileNetV2 convolutional neural network (ImageNet–pretrained, transfer–learned) trained on a validated dataset of 2,000 mulberry leaf images (500 per class), partitioned 80/10/10 into train/validation/isolated test with strict leakage control (content–hash union–find grouping and class–stratified splitting). Evaluation follows a single, pre–registered scoring pass on the isolated test split reporting accuracy, precision, recall, and F1–score per class and macro–averaged, with acceptance thresholds fixed before any run (accuracy and macro metrics ≥ 0.60; per–class metrics ≥ 0.40; test n ≥ 30). Early raw–photo runs reached 0.81 accuracy / 0.71 macro–F1 on in–domain held–out data; a full acceptance evaluation on the current validated cut is in progress. This document reports the complete, defensible methodology, the verified data partition, and the result–reporting framework used to claim that LEAFNET is a reliable, user–grounding diagnostic aid for sustainable mulberry production.

Keywords: machine learning, convolutional neural network, mulberry leaf disease, transfer learning, image classification, sustainable agriculture

CHAPTER 1 — INTRODUCTION

Situation Analysis

Global food security depends on protecting crops from pests and disease; biotic factors contribute roughly half of agricultural production losses (Shahbazi et al., 2025). Crop protection still relies heavily on manual field inspection and visual assessment in many production systems, which is slow, subject to human error, and often too late to prevent yield loss (Nicolas, 2024; AGRIVI, 2026). Modern agriculture increasingly addresses this with image–based, data–driven systems enabled by advances in agricultural intelligence and machine learning (Taha et al., 2025; Mesías-Ruiz et al., 2023).

Mulberry — the exclusive larval food of the mulberry silkworm — is economically important to sericulture. Its leaves are vulnerable to fungal and bacterial foliar diseases (rust, spot, blight) whose visual cues overlap: early rust resembles spot pinhead lesions, and coalesced spot can present a blighted appearance. This visual ambiguity motivates a controlled, evidence–reporting classifier rather than an unexplained "black–box" diagnosis.

Statement of the Objectives

This study develops and evaluates a four–class mulberry leaf classifier. Its specific objectives are:

  1. Develop a validated, leakage–controlled dataset and a reproducible 80/10/10 train/validation/test partition (mixed background conditions).
  2. Train a MobileNetV2 transfer–learning model and, through the pipeline, compare transfer–learning strategies (frozen backbone baseline, block fine–tune, full fine–tune).
  3. To test and evaluate the performance of the proposed machine learning model using appropriate evaluation metrics in terms of (1.1) accuracy, (2.2) precision, (3.3) recall, and (4.4) F1–score, judged against pre–registered acceptance thresholds on an isolated test set.
  4. Report generalization behavior (train vs. validation vs. test gaps) and distribution–shift (controlled–background vs. in–field) evidence so every claim is auditable.

Scope and Limitations

The classifier is a visual assessment tool: it reports what a leaf resembles, not a biological etiologic diagnosis. Symptoms that cannot be confidently assigned are routed to expert review and are never forced into a class. Generalization is bounded by the collection sites and device mix of the training corpus.

CHAPTER 2 — METHODOLOGY

Research Design

This study used a developmental and evaluative research design. The developmental design (Kumar, 2025) framed the systematic design, implementation, and iteration of LEAFNET through the Machine Learning Development Life Cycle (MLDLC) (§Procedures). The evaluative design (Trymata, 2025) assessed the resulting models against pre–registered criteria — accuracy, precision, recall, and F1–score — measured on an isolated held–out test split. All acceptance thresholds (ml/src/config/acceptance.json) were fixed before training and were never adjusted after results were observed; the verdict is advisory, and a human still decides promotion/activation through the model lifecycle.

Materials

Hardware

  • Development workstation/laptop with a multi–core CPU, ≥16 GB RAM, and a CUDA–capable GPU used to train the CNN.
  • Storage ≥512 GB SSD for the image corpus, trained checkpoints, and source.
  • Smartphones / digital cameras capturing field leaf photos during collection.
  • On–site or cloud hosting for the deployed REST services.

Software

  • Python ≥3.14 / PyTorch + torchvision — preprocessing, model definition, training, evaluation. MobileNetV2 weights (ImageNet–pretrained) are cached and verified; training is fully offline.
  • Pillow, NumPy — image handling and statistics.
  • scikit-learn — accuracy/precision/recall/F1 and confusion–matrix computation in the evaluation pass.
  • uvicorn / FastAPI-style REST service — the ML pipeline runner and inference endpoints (:8000); a Node.js REST API (:4000) serves dataset manifests, model registration, and the web application.
  • PostgreSQL — dataset versions, images, classifications, annotations, model versions, feedback.
  • Git/GitHub — version control and audit trail; pytest for regression tests on the splitter, preflight, and evaluation logic.

System Architecture

LEAFNET follows a clean three-tier, microservice–oriented layout with a strict ML/API boundary: the application layer never spawns Python processes, and all ML work flows over HTTP. This lets the pipeline be developed, scaled, and deployed independently (e.g., as a GPU worker).

Procedures (MLDLC Phases)

  1. Data ingestion and validation. Raw photos are uploaded, content–hashed (SHA–256), deduplicated (21 flagged duplicates removed; near–duplicates routed to human review), and recorded with provenance. Only APPROVED rows may train.
  2. Preliminary annotation and expert review. `Preliminary → Expert review`; uncertain/needs–review images never enter training; AI predictions can never write an annotation.
  3. Dataset versioning. A cut is locked (datasetId, versionLabel, seed) and its manifest becomes the single source of truth.
  4. Leakage–controlled splitting (details in §B).
  5. Preflight. The pipeline hard–refuses a manifest with an absent class, a class lacking test/validation coverage, duplicate content straddling splits, or degenerate split sizes (ml/src/training/preflight.py).
  6. Training. MobileNetV2 transfer learning per experiment configuration (Table 1), with early stopping on validation loss.
  7. Evaluation. One scoring pass per candidate on the isolated test split, with integrity re–checks (ml/src/evaluation/evaluate.py).
  8. Registration and human promotion. Every candidate is registered in the database (never auto–active); expert approval promotes it to active.

Preprocessing & augmentation

Images are letterbox–resized to 224×224 and normalized with ImageNet statistics. A photometric reference normalization scales each image so its mean leaf brightness lands on a reference value (0.343) computed from training–only statistics, neutralizing lot–to–lot illumination/processing drift across the dataset (applied identically at train and eval; leak–safe). Training augmentation (eval keeps none) applies horizontal flip (p=0.5), rotation ±10°, and color jitter ±0.3 to mirror handheld capture variance.

B. Dataset Splitting — 80/10/10 with Leakage Prevention

Total 2,000 images, partition 1600 / 200 / 200 (80 / 10 / 10), computed by create_grouped_splits (ml/src/data/splitting.py):

  1. Union–find over identity + content hash. Images sharing any grouping key (collection_session_id > farm_id > plant_id > leaf_id) or an equal SHA–256 are merged into one leakage component — exact duplicates can never straddle splits even when uploaded under different provenance.
  2. Whole–group assignment (grouped path). Groups are placed per class toward 80/10/10; a class with ≥3 groups is guaranteed ≥1 whole group in test and in validation, so coarse sessions cannot make a class unmeasurable.
  3. Class–stratified fallback (raw, ungrouped photos). When no grouping metadata exists, every class is apportioned its own 80/10/10 (≥1 test and ≥1 validation row for a class with ≥3 rows), so a class can never be silently unmeasurable. Within a class, in–field (natural–background) images are prioritized into test for distribution–shift evaluation; unlabeled rows go to train.
  4. Global rebalance then nails the exact declared partition without ever draining a class’s last held–out row.
  5. Audit. Every manifest writes .audit.json recording strategy, seed, final/per–class counts, background distribution, and drift vs. target, so partitions are verifiable after the fact.

Data Analysis

Performance was quantified on the isolated test split using standard scikit–learn metrics (accuracy, precision, recall, F1) averaged macro–wise and computed per class:

Accuracy = (TP + TN) / (TP + TN + FP + FN)   (1)
Precision = TP / (TP + FP)   (2)   |   Recall = TP / (TP + FN)   (3)
F1 = 2 · (Precision · Recall) / (Precision + Recall)   (4)

Legend: TP = true positive; TN = true negative; FP = false positive; FN = false negative.

Consistency & calibration analysis (mean confidence on correct vs. incorrect, high–confidence errors, difficult low–margin cases) is reported alongside, and confusion matrices accompany every verdict. In–field (natural–background) rows are analyzed separately as the out–of–distribution reference.

The corpus mixes controlled–background (lab–type) and in–field (natural–background) photos, giving the test split real–world distribution variety while standardized preprocessing governs illumination drift.

Discriminative Ability

Per–class precision/recall/F1 with support and the full confusion matrix accompany every verdict; per–class recall reveals which classes are missed. A ROC–AUC analysis and reliability (ECE) calibration curve are planned additions to reach full parity with the reference manuscript's analysis depth (requires the 200–image test set, which provides a statistically credible n).

Distribution–Shift and Confidence Analysis

The evaluator reports controlled–background vs. in–field key–metric differences (mild covariate shift) and characterizes errors: mean confidence on correct vs. incorrect decisions, counts of high–confidence errors (≥0.8 confidence but wrong), and difficult/low–margin cases (margin < 0.10 or confidence < 0.50). These make the numbers interpretable rather than merely "high".

CHAPTER 4 — SUMMARY, CONCLUSIONS, RECOMMENDATIONS

Summary

LEAFNET operationalizes a defensible, reproducible four–class mulberry leaf classifier: a validated 2,000–image corpus, a leakage–controlled 1600/200/200 partition with every class measurable in test and validation, pre–registered objective thresholds, and a single auditable evaluation pass per candidate.

Conclusions

  • Objectivity: acceptance is decided by pre–registered accuracy / precision / recall / F1 thresholds on an isolated, integrity–checked test split — never by thresholds tuned after results.
  • Measurable every class: the stratified split guarantees every class appears in test and validation, so worst–class performance cannot be hidden.
  • Leakage–free: content–hash union–find + grouped assignment make split contamination structurally impossible and audit–verified.
  • Evidence until a candidate passes, the results above remain a research– methodology claim, not an acceptance claim.

Recommendations

  • Complete the v1.0 acceptance run to populate Tables 4 & generalization figures.
  • Add ROC–AUC + reliability diagrams to the evaluation pass for parity with the reference manuscript.
  • Collect more in–field (natural–background) images for underrepresented classes to shrink distribution–shift gaps, mirroring the reference's limitation discussion.
  • Report top–2 agreement and margin statistics to surface spot–vs.–blight ambiguity.
