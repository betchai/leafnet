## 1. Covariate-Shift (Out-of-Distribution) Evaluation (#3)

To measure model performance on in-situ natural-background field photos vs. curated white-background removed images without manual tagging, we introduced automatic background classification and telemetry:

### A. Automatic Background Classification (ML)
- **Algorithm:** Implemented `detect_background()` in `ml/src/inference/symptom_analysis.py` using color-space heuristics (luminance & chroma variance outside the segmented leaf region).
- **Classification Categories:**
  - `white_removed`: Near-uniform, near-white background (curated research images).
  - `natural`: In-situ field backdrop containing soil, grass, or sky.
  - `unknown`: Fallback for pathological cases.
- **Degenerate Guard:** Added a leaf-area threshold filter (`leaf_fraction < 0.05`) to prevent blank/off-frame images from being misclassified as `natural`.
- **Model-Free Route:** Exposed the capability on a model-free endpoint `/tag/background` (reachable on port `:8000`), allowing tagging even when the service is unhealthy due to lack of an active model.

### B. Ingest and Storage Persistence (API)
- **Prisma Schema Update:** Added `backgroundType` column to the `Image` model.
- **Migration:** Created and applied the migration script `20260831154010_add_background_type`.
- **Ingest Integration:** Wired the API's `ingestImage` service (`apps/api/src/services/ingestion.ts`) to call `/tag/background` at ingest (LabelTool & BulkIngest) and persist `backgroundType` on the row. 
  - *Non-Fatal Fallback:* Ingestion remains highly resilient; if the ML service is unreachable, images still ingest successfully (tagging is treated as best-effort).
- **Dataset Manifest:** Included `background_type` in the reproduicible JSONL output served by `/api/datasets/:id/manifest`.

### C. Distribution-Aware Dataset Splitting (ML)
- **Location:** `ml/src/data/splitting.py`
- **Logic:** Extended the leakage-safe, group-aware splitter to stratify splits using both class and `background_type` representation.
- **OOD Preservation:** Prioritizes ungrouped `natural` (OOD) background rows into the test split, ensuring that evaluation has sufficient support to measure distribution shift.
- **Audit Logging:** The split metadata audit now reports `background_dist` showing exact image counts per background type per split.

### D. Per-Domain Metric Evaluation (ML)
- **Location:** `ml/src/evaluation/evaluate.py`
- **Metrics Computed:** Computes accuracy, macro-F1, and per-class F1 separately for `white_removed` vs. `natural` test sets, reporting performance gaps reflecting mild covariate shift.
- **Honest Telemetry:** Emits a `no_domain_test_data` boolean flag and clear explanatory findings in the model metrics when no in-situ `natural` images exist in the test split.
- **Artifact:** Outputs a new `distribution_shift.json` file in the model's metrics folder.

### E. OOD Drift Insights & Monitoring (API & ML)
- **Research Insights:** Built `distribution_shift_insights` into the python analytics pipeline (`ml/src/analytics/insights.py`) to report OOD performance gaps, returning descriptive findings (or warning of zero-data).
- **Application Insights:** Overhauled `/api/insights` in the API (`apps/api/src/routes/toolsInsights.ts`) to group served predictions by `backgroundType` x feedback verdict.
- **Telemetry:** Exposes the growing in-situ OOD pool size and tracks the number of verified-corrected labels (Expert review disagreeing with model prediction on a natural background) which serve as labeled OOD candidates.

## 2. B+C Hybrid Explain Feature

Implements leaf symptom measurements and criteria profile comparisons for transparent explanations (completed earlier in this session):

- **CV Feature Extraction:** `ml/src/inference/symptom_analysis.py` extracts necrosis fraction, spot density, rust pustule signal, and green-leaf fraction.
- **Voter Matrix:** `ml/src/inference/criteria_profiles.py` houses criteria profiles per class pair, registering votes supporting the primary class, second class, or flagging as inconclusive.
- **Passthrough & UI:** Connected the API prediction handler to pass through `criteria` and `measurements` to the web client, rendering per-criterion details in the Analyzer page (`Analyzer.tsx`).
